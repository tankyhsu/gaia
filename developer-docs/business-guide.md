# 业务构建者指南

你不需要先掌握 Python 或理解 Gaia 的内部结构。先判断一件事：这个业务想法能不能通过一个
简单 Demo 被验证。

## Gaia 能帮你先做什么

| 业务目标 | Demo 可以先呈现什么 | HR 参考示例 |
| --- | --- | --- |
| 处理文本和文档 | 总结、分类、信息抽取和内容生成 | 简历阅读 |
| 基于企业知识回答 | 根据指定资料回答，并标明信息来源 | 员工手册 |
| 连接并操作业务系统 | 查询或执行操作，在关键步骤等待人工确认 | 请假办理 |

Dev Console 的“快速开始”会把参考示例登记在对应模板下。你可以先打开示例理解最终体验，
再决定使用哪个模板创建自己的 Demo。

即使是 Demo，也可以保留必要的安全边界：内容进入模型前识别风险，企业资料进入回答前检查
权限，系统操作执行前后检查参数和结果。Gaia 会把放行、脱敏、阻断及检查异常记录到对应 Run，
便于开发人员解释结果，而不是保存被检查的业务正文。

## 你需要准备什么

开始时只需要四样东西：

1. **一个使用者**：谁会用这个 Demo。
2. **一个具体任务**：他希望节省哪一步工作。
3. **少量真实样本**：5 到 10 条具有代表性的输入。
4. **一个判断标准**：看到什么结果，才说明这个方向值得继续。

模型、知识库和业务接口可以先使用示例能力。场景得到验证后，再请开发人员接入真实环境。

## 推荐路径

1. 按[用模板搭一个 Demo](demo.md)明确输入、输出和场景模板。
2. 在 Quick Start 中生成项目起点。
3. 用真实样本检查结果、边界情况和人工确认点。
4. 在“运行 → 安全决策”查看哪些内容被放行、改写或阻断。
5. 记录缺少的企业资料、业务规则和系统接口。

当你需要修改代码、连接真实系统或建立质量测试时，可以把项目交给开发人员，并让他从
[开发者指南](developer-guide.md)继续。
