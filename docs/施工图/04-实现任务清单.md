# 04 Gaia Framework M1 实现任务清单

## 1. 执行规则

- T01-T04 串行，先建立框架内核再切 Runtime；
- T05-T07 在 T04 之后可以并行；
- T08-T10 必须在实现冻结后执行；
- 子 Agent 只能修改任务列出的文件；需要跨边界时先通知主 Agent；
- 每个任务必须新增测试，不能只让旧测试继续通过；
- 不得用前端静态数据模拟后端尚不存在的框架能力；
- 不得删除 Runtime 可靠性断言来迁移示例；
- 不得在核心包新增客户、行业、实施方法论或 controlled-task 语义。

## T10 独立子 Agent 验证

**前置**：实现冻结。

验证 Agent 只允许阅读：根 README、公开配置 schema、CLI help、OpenAPI 和 examples。

它必须独立完成：

1. `gaia init` 生成应用；
2. 修改 Profile 并通过 `gaia check`；
3. 启动应用并通过 Actuator 发现组件；
4. 在 Dev Console 核对当前生效配置、字段来源和配置指纹；
5. 完成 controlled-task Run、审批、SSE；
6. 运行 10-case replay；
7. 重启应用进程并确认历史 Run、事件和 Replay 数据保留。

失败保留在 `examples/framework-validation/FINDINGS.md`，由主 Agent 分类修复后让同一 Agent 重测。

- pgvector HNSW/IVFFlat 索引及应用注入 embedding；
- OpenAI-compatible EmbeddingProvider、SecretRef 和硅基流动 reference profile；
- PostgreSQL 可选依赖、生成项目依赖和开发基础设施 Compose；

## T12 Runtime 安全边界与 Integration Sandbox

**允许修改**：公共契约、Runtime、配置模型、生成模板、reference profile、测试和相关文档。

**实现**：

- `runtime.environment` 成为服务端唯一安全事实，请求只能声明并匹配；
- 环境写入上限与场景 `ExecutionPolicy.write_mode` 取更严格值；
- 写工具同时注册 `ToolDefinition` 与 Factory，并声明允许环境；
- Runtime 在 Adapter 实例化前校验工具白名单、角色、风险、环境和写入权限；
- Adapter 定义漂移和执行异常转为可审计失败；
- 生成项目提供 mock/sandbox/customer 安全默认配置；
- 任意代码执行 Sandbox 保持为独立触发项，不进入 Runtime 默认依赖。

**验收**：

- 客户端不能通过 `RunRequest.mode` 切换服务端环境；
- Sandbox 的所有写操作必须经过 HumanGate；
- Customer 默认禁止写入；
- 未注册工具、未授权工具、角色不足、风险降级和 Adapter 漂移均在执行前失败；
- Mock 与 Sandbox profile 均通过 `gaia check`，全量回归和 wheel 构建通过。

## T13 Redis Cache/Rate Limit 与 PostgreSQL Outbox

**允许修改**：SDK、Integration/Capability、配置、Starter、持久化模型与迁移、Compose、生成模板和相关测试。

**实现**：

- `CacheProvider` 与 `cache-redis` Starter，强制 TTL 和 namespace；
- `RateLimiter` 与 `rate-limit-redis` Starter，Redis Lua 原子固定窗口；
- Redis optional extra、SecretRef、共享 Client 资源和 Compose overlay；
- `EventEnvelope/EventPublisher` 与进程内 Publisher；
- PostgreSQL Transactional Outbox、事务内 enqueue、租约、重试和死信；
- `outbox-postgres` 自动补齐 PostgreSQL 与进程内 Publisher 依赖；
- Kafka/RabbitMQ 只保留 `EventPublisher` 扩展边界，不引入客户端。

**验收**：

- Redis 不保存 Run、Gate、Command、审计、Outbox 或长期记忆事实；
- Cache TTL 与限流在真实 Redis 上通过；
- Outbox 与业务事务共同提交或回滚；
- 两个 PostgreSQL Worker 使用 `SKIP LOCKED` 时不重复领取；
- 失败投递达到阈值进入 dead letter；
- 生成项目正确组合 `[redis]`、`[postgres]` 或两个 extra；
- 全量回归、迁移、wheel 和文档检查通过。

## T14 Python 原生资源与集成边界

**允许修改**：Application、Component、Starter、Integration/Capability 目录、ASGI composition
root、架构测试和相关文档。

**实现**：

- `configure()` 只生成 ComponentSpec 和装配报告，不实例化组件或连接外部系统；
- 普通 Factory 接收已解析依赖，Resource Factory 返回异步上下文；
- `GaiaApplication.lifespan()` 使用 `AsyncExitStack` 管理 application-scoped 资源；
- FastAPI lifespan 成为数据库、Gaia 组件和应用资源的唯一根作用域；
- Redis 移入 `integrations/`，Cache 与 RateLimiter 共享 redis-py Client；
- Outbox 移入 `capabilities/`，不再作为持久化 Client；
- 架构测试固化 Core、Integration、Capability Pack 和客户 Adapter 的依赖方向。

**验收**：

- 配置后组件实例为空且没有资源副作用；
- 依赖实例可由下游 Factory 读取；
- 任一资源进入失败，先前资源逆序释放；
- lifespan 退出后 Context 不暴露已关闭组件；
- 真实 Redis、PostgreSQL、ASGI、wheel 与全量回归通过；
- 源码和权威文档不再引用 `gaia.adapters.redis` 或 `gaia.persistence.outbox`。
