目标：`make demo` 之后，一个**没读过这个项目的人**打开浏览器，三分钟内能说出
"这东西是干什么的、刚才那三条运行分别证明了什么"。达不到这个标准就不算完成。

这不是美化任务。当时有三个具体缺陷，每一个都会让演示当场失败。

## 现状缺陷（已实测，2026-07-30）

跑 `make demo` 后打开 `http://127.0.0.1:4180/#runs`，实际看到的是：

### 缺陷 1：把"控制生效"显示成"系统出故障"

首屏最大的两个数字是 **成功率 33.3%**、**失败率 0.0%**。三条种子数据里有两条是
`blocked`——它们是**人工拒绝**和**跨组织策略拒绝**，也就是这个框架存在的理由。
首屏却把它们算进了"不成功"。

紧接着的「需要处理」表把这两条列为待处理问题，「瓶颈」一栏写 **运行错误**。
`HUMAN_GATE_REJECTED`（人拒绝了）和 `FORBIDDEN`（策略拦了）都不是运行错误。

**这是本项目最不该犯的错误**：整个 Gaia 的卖点是"证据必须诚实"，而它自己的首屏
在对着演示对象说假话——把成功的控制说成故障。

### 缺陷 2：首屏是运维仪表盘，不是演示

- 「等待与容量」整块是 `0` 和 `-`（活跃 Run 0、最久人工等待 -、数据库连接 - / -、
  Outbox 0、重试/死信 0/0）。演示场景下这些永远是空的，纯噪音。
- 演示真正的内容——「最近运行」和点进去的证据页——被压在首屏之下。
- 页面上没有任何一句话说明这是什么、该看什么。
- Run ID 以 `gaia-run-5b26e91de8b941db75f7e4befe07cd57` 全长显示并折行，占满一列，
  没有任何可读信息。

### 缺陷 3：文档链接全是死链

`apps/web/src/Console.tsx:80` 硬编码：

```ts
const DEVELOPER_DOCS_URL = import.meta.env.VITE_GAIA_DOCS_URL || `...:4175/`;
const SHOWCASE_URL       = import.meta.env.VITE_GAIA_SHOWCASE_URL || `...:4173/`;
```

而 `scripts/demo.py` **不启动这两个服务**（全文无 mkdocs / 4175 / 4173）。于是：

- 侧边栏「Gaia 文档」→ 连接被拒绝
- `Console.tsx:658` 的 `mechanisms/` 深链 → 死链
- `Console.tsx:1046` 的 showcase 示例链接 → 死链

演示时点开侧边栏第一个外链就是错误页。

## 不可违反的约束

1. **不许为了好看而说假话。** 这是全项目的第一原则。`blocked` 是控制生效，不是失败；
   没有数据就显示"暂无"，不要显示 `0` 假装测量过；不确定的事实写"未记录"，
   不要猜（参考 `docs/工程纪实-决策与缺陷.md` 里 H0 那条"证据视图说谎"的教训）。
2. **不许动 `src/gaia/runtime/safety.py`。**
3. **不许放宽或删除任何既有测试断言**来让新 UI 通过。测试改动只允许是"新 UI 的新断言"
   或"旧断言表达的行为确实按本文要求变了"，后者必须在提交信息里说明。
4. **运维视图的能力不能退化。** 运维需要的指标不是删掉，是挪到该在的地方。
5. 每个任务结束时 `make verify` 必须通过（含 13 个 Playwright 用例）。

## 任务 D3（最高优先级，已改写）：让证据页说人话

> 2026-07-30 现场复核后改写。原 D3 是排版任务，已降级为 D4。
> 真正的问题是：**点了「看证据」之后，看的人完全不知道自己在看什么。**

### 实测记录（demo 三条种子数据，点第三条「已完成」的看证据）

落地后从上往下依次是：运行指标 → 等待与容量 → 需要处理 → 最近运行 →
按 Run ID 查询 → **然后才是证据**。证据在第五屏以下。

证据区本身的内容顺序与文案：

| 区块 | 实际渲染 | 问题 |
| --- | --- | --- |
| 依据哪版策略 | 策略 ID `policy-controlled-task`、版本 1.0.0、运维收紧 否 | 把**最不像人话的元数据放在第一屏**。看的人想知道"发生了什么"，先看到的是策略 ID |
| 内容指纹 | 工作流/业务规则/Prompt/模型档案/工具集/上下文档案 六行，**每行都是 `1.0.0` + "手填版本号，不是内容指纹"** | 六行重复否定句。读者只会得到"这里六样东西都没做"的印象，像坏了 |
| 谁批准的 | Gate `gaia-run-5d86…:gate:execute_side_effect`、已批准、demo-approver | 这是**全页最有价值的一块**，却排在两块噪音之后 |
| 什么被拒了 | "这个 Run 里没有任何调用被拒绝。" | 尚可 |
| 状态轨迹 | 13 条 `receive_request` / `interpret_intent` / `authorize_context` / `propose_side_effect` … 全是英文 snake_case 内部步骤名 | 中文界面里 13 行英文内部符号，看不出**哪一步才是关键**（create_human_gate → human_gate_approved → execute_side_effect） |

### 一个必须先修的事实错误

状态轨迹下面写着：

> 每一次状态写入都会经过 `src/gaia/runtime/lifecycle.py` 里的迁移表校验，
> 非法迁移在测试期就会失败，而不是在生产里悄悄发生。

**`src/gaia/runtime/lifecycle.py` 在 Temporal 迁移里已经删除了**
（`apps/web/src/Console.tsx:2569` 仍在引用它）。状态迁移现在由 Temporal Workflow
拥有，保障机制是 `tests/integration/test_workflow_replay.py` 的历史回放守卫。

**证据页在为一个已经不存在的控制背书**——这正是 H0 那条"证据视图说谎"的重演，
方向相反但性质相同。修它是这个任务里唯一不可协商的部分。

### 要做成什么样

1. **独立路由 `#evidence/<run_id>`**，不是运维页底部的一段。「看证据」直接落在这一页，
   打开即见证据，不需要滚过任何运维指标。
2. **第一屏先回答"发生了什么"**：一段人话，由真实数据生成（不许硬编码、不许猜）。
   例如"operator 发起了一次高风险写入 → 触发人工审批 → demo-approver 批准 → 写入执行成功"。
   拿不到的环节就不写那一句。
3. **重排**：发生了什么 → 谁批准的 → 什么被拒了 → 依据哪版策略 → 状态轨迹。
4. **状态轨迹**：默认只展开关键步骤（建 gate、批准/拒绝、执行写入、终态），
   其余折叠；步骤名给中文标签，**原始英文名保留在 title 或展开处**，不要丢失可核对性。
5. **内容指纹**：六行折叠成一行结论（如"6 项版本均为手填版本号，未启用内容指纹"），
   展开可看明细。
6. **长标识符**：Gate ID、策略 ID 用短显示 + 复制，全量放 `title`。
7. **改掉 `Console.tsx:2569` 的失效引用**，换成现在真正成立的说法，或者删掉这句话。
   **不许保留一句无法核实的背书。**

### 验收

- 点「看证据」后**第一屏**就能读懂这次运行发生了什么、谁批准的
- 页面上不存在指向已删除文件或已不存在机制的说明文字
- 三条种子数据各点一遍，页面陈述与实际结果逐条相符
- 新增 Playwright 用例覆盖：直达证据页、第一屏摘要文案、关键步骤高亮
