# 07 质量策略与测试矩阵

本文定义 Gaia 自身的工程质量门禁。应用如何使用 Gaia Test Kit 验证 AI 行为，见
[08-Gaia Test Kit 设计](08-Gaia-Test-Kit设计.md)。两者不能混为一个综合“评估分数”。

## 1. 测试金字塔

| 层级 | 目标 | 速度要求 |
| --- | --- | --- |
| Unit | 配置合并、Condition、Registry、生命周期、Policy 纯逻辑 | 全套秒级 |
| Contract | Starter、Provider、Tool、Actuator、OpenAPI 契约 | 不访问真实外部服务 |
| Integration | Application 装配、数据库迁移、Runtime、恢复、API | SQLite 快速套件 + 真实 PostgreSQL 扩展套件 |
| Architecture | import 边界、示例与框架隔离、禁止硬编码业务语义 | AST/静态扫描 |
| Acceptance | controlled-task 通过框架装配后的原验收集 | 结果和副作用均断言 |
| E2E | CLI 生成项目、业务场景初始化、Dev Console 观察、Run/审批/Replay | Docker/浏览器 |
| External | 陌生子 Agent 只读公开资料完成新应用和配置 | 核心实现冻结后 |

## 2. Unit 必测场景

### Config

- 默认值、Starter defaults、YAML、Profile、env、CLI 的覆盖顺序；
- list 整体替换；
- 类型错误和未知字段失败；
- SecretRef 不泄漏；
- config hash 稳定；
- 旧环境变量告警。

### Registry 与 AutoConfig

- 唯一组件注册；
- 显式实现覆盖默认实现；
- required dependency 缺失；
- dependency cycle；
- singleton ambiguity；
- positive/negative condition report；
- Factory 依赖解析和 Resource Factory 逆序退出。

### Application

- configure 零资源副作用；
- application lifespan 正常进入和退出；
- 资源进入中间失败后逆序释放；
- failed 状态禁止重启；
- context 不可变；
- lifespan 退出后清空已关闭组件；
- Actuator snapshot 脱敏。

## 3. Contract 必测场景

- 每个内置 Starter 具有 descriptor、默认值、条件和可构造 Factory；
- ComponentDescriptor JSON 稳定；
- Actuator endpoint schema 与 Pydantic/OpenAPI 一致；
- Runtime API 保持向后兼容；
- 示例 Starter 可以通过 import path 加载。

## 4. Integration 必测场景

- 从 example `gaia.yaml` 启动完整 Application；
- active Profile 正确装配组件；
- Actuator 配置 hash、字段来源与实际启动配置一致；
- API 不暴露配置写入或运行时热替换端点；
- 新 Run 冻结新 version bundle，旧 Run 不变化；
- 组件健康失败反映到 Actuator，不触发外部写操作；
- 原有并发审批、Command CAS、unknown reconcile、恢复测试继续通过；
- 历史数据卷升级到最新迁移且不丢 Run/Event，并清理已退役控制面表；
- PostgreSQL Alembic head、事务提交与回滚；
- PostgreSQL checkpoint 跨 provider 重启恢复；
- PostgreSQL long-term memory CRUD、过滤、pgvector 检索和重启持久性；
- OpenAI-compatible embedding 协议、批处理、响应顺序、维度和错误映射；
- 硅基流动真实 embedding 响应，以及 embedding -> pgvector -> 中文召回；
- PostgreSQL 开发依赖健康、完整 Run 和 Actuator Secret 脱敏。
- 服务端 environment 拒绝不匹配的 Run mode；
- Tool environment 在 Runtime 构造阶段校验；
- Sandbox 所有写入进入 HumanGate，Customer 默认阻断写入；
- 工具白名单、角色、风险或 Adapter 定义漂移均在真实副作用前失败。
- Redis Cache namespace、TTL 上限和真实过期；
- Redis RateLimiter 的 Lua 原子计数、额度耗尽与 retry-after；
- Outbox 与业务事务共同提交或回滚；
- Outbox 租约、重试、死信和至少一次投递；
- PostgreSQL 两个 Worker 通过 `SKIP LOCKED` 不重复领取同一事件。

## 5. 架构门禁

AST 测试必须失败于：

- `src/gaia/runtime` import `examples`、`scenarios` 或具体 Mock；
- `src/gaia` 出现 `res-001`、`org-alpha`、`controlled-task` 业务常量；
- `examples` import `gaia.persistence.models`；
- Dev Console source 硬编码组件清单或 active config；
- 核心模块 import FastAPI/React 依赖；
- 施工图再次把客户发现或实施方法论定义为 Gaia 产品身份。
- 模型、Workflow 或请求字段可以降低 ToolDefinition 风险或切换服务端 environment。

## 6. CLI 验收

临时目录执行：

```bash
gaia init sample --starter model-mock --starter workflow-langgraph
cd sample
gaia check
pytest
```

断言：

- 生成文件完整；
- 第二次生成拒绝覆盖；
- 错误 Starter 退出 2；
- 缺失 Secret 退出 2 且不打印 Secret；
- 生成应用能导入并建立 ApplicationContext。

## 7. Dev Console E2E

Playwright 至少覆盖：

1. 首次进入显示可跳过的 Quick Start，并可选择场景模板和推荐组件；
2. 概览展示真实 Application/Profile/组件健康；
3. 组件页聚合 Provider、实现、来源、装配和健康状态；
4. 配置页只读展示生效配置、字段来源和配置 hash；
5. Run、审批、事件、Replay 入口仍可用；
6. 1440x900 与 390x844 无溢出、遮挡和空白主画面。
7. Gaia 文档首页可以分别进入业务构建者与开发者路径，两条路径的侧边导航互不混排。

## 8. 质量命令

```bash
make agent-check
git add <intended-files>
make change-ready
make verify
```

确定性测试使用 `not postgres and not redis and not external`；PostgreSQL 与 Redis 由 GitHub
service container 在每个 Pull Request 运行。SiliconFlow 等外部服务必须同时具有
`external` marker、`RUN_EXTERNAL_TESTS=1` 和对应凭据，研发阶段只允许开发者显式手工触发，
不得进入 Pull Request 或 main push 的自动门禁。

`make change-ready` 生成与 staged tree 绑定的验证凭证。Codex `PreToolUse` 在执行
`git commit` 前校验凭证；`Stop` 和 `SubagentStop` 在修改性任务结束前执行影响分析和必要检查。
GitHub Actions 不信任本地凭证，而是在干净环境独立复现。

禁止通过删除断言、放宽 schema、过滤自有 warning 或把失败测试标记 skip 来完成迁移。
