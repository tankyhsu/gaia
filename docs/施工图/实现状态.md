# Gaia Framework M5 实现状态

更新日期：2026-07-24

## 当前阶段

状态：**M5 评审 P1/P2 增强完成。**

Gaia 已从特定交付 Demo 重构为通用 AI 应用开发与运行框架。核心包不包含客户、行业或
`controlled-task` 业务实现；参考业务仅位于 `examples/controlled_task/`。

- 严格 `gaia.yaml`、Profile、`--profile`/环境/CLI 覆盖、SecretRef 和配置来源；
- 内置与 import Starter、条件装配、组件依赖图和装配报告；
- Model、Workflow、Context、Tool、Policy 组件契约及 Replay 兼容 Starter；
- 开发期 Gaia Test Kit：版本化 JSON/YAML Dataset、CaseExecutor、Evaluator、QualityGate 和 TestReport；
- 通用 PassRateGate：Case 阈值、Suite 通过率、重复执行聚合、关键 Case 和标签分组门禁；
- 通用 Runtime 依赖注入、HumanGate、副作用 CAS、恢复、审计和 SSE；
- Actuator info/health/components/config/conditions；
- `gaia init/check/doctor/add-workflow/dev/test/starters/migrate` CLI 与可独立安装 wheel；
- 无业务常量、独立部署的 Gaia Dev Console；
- `controlled_task` 参考应用、10 个验收样本和重启持久化验证。
- PostgreSQL 事务持久化、托管连接池和框架内置 `gaia migrate`；
- LangGraph PostgreSQL checkpoint、PostgreSQL long-term memory 与 pgvector；
- 通用 EmbeddingProvider、OpenAI-compatible 实现和硅基流动 reference profile；
- SQLite 默认 profile 和 PostgreSQL 扩展 profile 双路径。

- `sandbox` reference profile，以及生成项目的 mock/sandbox/customer 安全默认配置。
- redis-py Integration、共享 Client、CacheProvider/RateLimiter 与可选开发基础设施；
- Capability Pack 形式的 PostgreSQL Transactional Outbox、进程内 Publisher、租约、重试与 dead letter；
- Core、Integration、Capability Pack 与客户 Adapter 的架构测试边界。
- 稳定机器错误码、人类可读错误、重试语义、处理建议和 Trace ID；
- `gaia doctor` 对数据库、Redis、模型和 Embedding Endpoint 的显式连接诊断；
- Run、HumanGate、错误、Outbox、连接池和 PostgreSQL 等待的通用运行摘要；
- Dev Console 首次进入显示可跳过的 Quick Start；初始化中的项目可选择场景模板和按需组件，
  完成后入口只保留说明，概览只保留当前应用状态；
- 独立 Gaia 文档站以受众分流为首页：业务构建者从能力、模板和 Demo 验证进入，开发者从内部
  机制、项目初始化、CLI 和 API Reference 进入；Console 只保留导航入口，HTTP API 由 FastAPI
  OpenAPI 独立生成；
- Console 配置只读展示生效值与字段来源；Run 详情以结果、模型调用、安全决策和事件链四个
  Tab 内聚呈现，审批和测试结果使用指标与表格，不直接展示 JSON；
- Console 近 24 小时运维概览，以及停滞 Run、待确认和基础设施积压视图；
- 应用自有 Workflow 节点与路由生成模板，框架不保存业务 State、节点或规则。
- `ScenarioSpec`、`@scenario` 和 `FunctionScenarioRunner`，普通异步函数仍进入统一受控 Runtime；
- `@read_tool` 与受约束的 `@write_tool`，写入必须声明风险、角色、环境和 `reconcile`；
- `ApiDependencies.from_scenarios()` 显式装配场景与写工具，不使用全局注册表；
- `gaia init` 生成基础请求、知识检索或受控操作 Scenario、真实 Runtime 测试和所需组件配置；
- `gaia init` 生成 `create_application()` 工厂，测试不复用已停止的 Application 实例；
- `gaia dev --app ... --reload` 支持完整应用热重载；
- 配置路径统一为 `--config`、`GAIA_CONFIG_PATH`、默认 `gaia.yaml`；Prompt/RAG 资产目录以配置
  文件目录为基准，不再依赖进程 CWD；
- `PromptRef`、`PromptArtifact`、`PromptProvider` 和零配置外部 I/O 的 `prompt-file` Starter；
- `ModelInvocation` 与 `ModelUsage` 工程证据契约，不采集模型私有思维链；
- ADR 固定唯一 Runtime SPI、Prompt Artifact、部署单元和模型观测边界。
- PostgreSQL Prompt Registry：不可变版本、质量证据、mock/sandbox/customer 发布指针、回滚、
  退役约束与审计记录；
- 新 Run 在幂等记录落库前解析 Prompt 指针，并把精确版本和内容哈希固定到 VersionBundle；
- `gaia prompt import/diff/validate/publish/rollback`，发布报告必须绑定同一 Prompt Artifact；
- Dev Console Prompt 菜单稳定显示：disabled 提供 Provider 选择状态，file 提供无正文的
  Artifact 只读清单，postgres 提供版本、环境指针和导入三个 Tab；写路由仅由
  `GAIA_DEVTOOLS_ENABLED=true` 显式开启，Actuator 返回工作区开关状态。
- `InstrumentedModelProvider` 为 Mock 与 OpenAI-compatible Provider 生成同一
  `ModelInvocation` 证据，记录 Token、耗时、重试、错误和可选成本；
- 模型观测只持久化内容哈希与版本关联，不保存 Prompt、响应正文、Secret 或模型私有思维链；
- `SqlAlchemyModelInvocationStore`、`0008_model_invocations` 迁移和按 Run 查询 API；
- 可选 OpenTelemetry Sink；未安装 `otel` extra 时 Core 无强制依赖；
- Dev Console Run Inspector 展示调用数、Token、P95、重试及逐调用摘要，并展示五阶段
  Guardrail 的放行、改写、阻断、异常、规则版本和原因码；
- `DocumentLoader`、`DocumentParser`、`Chunker`、`Retriever`、`Citation` 公共契约；
- 受根目录限制的本地 Loader、UTF-8 文本 Parser 和确定性 FixedWindow Chunker 参考实现；
- `MemoryRagRepository` 使用 active generation 隔离更新中间态，并可在重试时清理旧 Chunk；
- tenant/corpus namespace、角色/用户权限过滤、文档版本、来源 URI、Chunk 哈希和权限依据；
- `rag-postgres` 显式 Starter，组合 PostgresMemoryStore、pgvector 与 Embedding；
- `minimal-cited-rag` Golden Dataset 覆盖命中、角色拒绝和跨知识域检索。
- OpenAI-compatible `generate_stream()`、厂商无关 `ModelStreamChunk` 和流式调用观测；
- 五阶段 Guardrail Pipeline、稳定阻断错误、Pattern 改写与流式增量检查；
- `GuardrailDecision` 无正文证据、`0009_guardrail_decisions` 迁移、按 Run 查询和
  fail-open/fail-closed/强审计语义；
- Presidio PII 与 Guardrails AI validate-only 可选适配器，不进入默认依赖和自动装配；
- 多 Agent 白名单 Handoff、共享状态、交接证据和 `max_handoffs` 硬预算；
- `gaia test` 直接运行应用 Test Kit 工厂和 Dataset，输出报告及 `0/1/2` 稳定退出码；
- Dev Console Nginx 动态解析 Compose 服务地址，并能正确处理非 JSON 网关错误。

Test Kit 提供测试骨架、确定性默认 Gate 和显式启用的通用通过率 Gate，不内建置信区间、
LLM judge 或评估平台。应用可以通过公共协议注入自己的指标与质量决策模型。

## 明确边界

- M1 不提供 HTTP 配置写入或运行时热替换，配置变更通过文件、环境和部署流程完成；
- Gaia 不负责容器、Kubernetes 或其他部署编排，部署层应用配置后以 Actuator 快照为准；
- import Starter 只能由代码和 `gaia.yaml` 声明；
- 两个现存 warning 来自 LangGraph checkpoint 与 Starlette TestClient 的上游弃用提示，不影响 M1 功能；
- Showcase 仍保持独立，后续只能消费 Gaia 公共能力。
- Gaia 运行摘要只包含框架级 Run、Gate、错误和基础设施状态；客户业务指标留在应用或外部可观测平台。
- Gaia Dev Console 作为独立本地开发进程显式启动，不进入生产应用安装包或基础设施服务图。
- Sandbox 是测试资源、凭据和 Adapter 的集成隔离；任意代码执行 Sandbox 仍为明确非目标。
