# 05 Gaia Dev Console 设计

## 1. 产品角色

Gaia Dev Console 是独立的开发期工具，承担两类任务：

- 业务构建者在 Quick Start 中选择场景并生成 Demo 起点；
- 开发者观察和诊断当前应用的真实装配与运行状态。

它不是客户业务页面、生产管理后台或配置发布平台。生产应用只加载 Gaia Python 核心包和应用
声明的 Starter，不部署 Console。

Console 按用户任务组织，而不是按框架内部模块组织：

- Quick Start：选择业务场景、推荐组件并完成初始化；
- 概览：当前应用是否就绪；
- 组件：各能力实际装配了什么实现、从哪里装配、是否健康；
- 运行：请求执行后发生了什么、哪里失败或等待；
- 配置：进程当前真正生效的配置是什么、每个字段来自哪里；
- 测试：当前版本能否通过确定性回放和质量门禁。

“启动检查”不设独立页面。配置加载、核心组件、依赖健康、Workflow 注册和最小成功 Run 都属于
概览的启动就绪判断。“排查运行”也不设独立页面；它属于运行页在存在真实 Run 后提供的观察和
定位能力。两者的时间边界不同，不重复展示同一组指标。

## 2. 信息架构

```text
Quick Start（首次进入默认显示，可跳过）
  - 选择业务场景模板
  - 了解内容、知识和系统操作的安全边界
  - 查看推荐组件并按需调整
  - 完成初始化或保留场景说明
概览
  - 启动与接入状态
组件
  - Provider 选择、注册结果、实现和来源 Starter
  - 必需性、装配状态、健康状态和错误
运行
  - 近 24 小时成功率、失败率、耗时和等待
  - 异常 Run、模型调用、安全决策、事件链和人工确认
配置
  - 当前生效配置
  - 配置指纹、重启状态和逐字段来源
测试
  - Replay 执行
  - 通过率和逐 Case 结果
```

Quick Start 只负责生成项目起点，不承载最终业务操作。真实 Demo 的输入、结果和操作界面属于
生成应用自己的 UI 或 Showcase，不进入 Dev Console。

## 3. 页面职责

### 3.1 Quick Start

生成项目首次启动 Console 且 URL 没有指定页面时，先显示一次性引导：

1. 用一句话说明 Gaia 是面向企业 AI 应用的 Python 开发与运行框架；
2. 让使用者从“处理文本和文档”“基于企业知识回答”“连接并操作业务系统”中选择起始场景；
3. 用业务语言说明内容进入模型、引用企业知识和执行系统操作时的安全检查；
4. 根据场景推荐组件，并允许按需调整后完成初始化；
5. 提供 Gaia 文档入口，由文档首页继续分流到业务构建者和开发者两套路径。

Quick Start 不提供 Guardrail Starter 开关。第三方防护需要语言资源、客户规则、风险阈值和失败
策略，应由开发者在真实场景中装配，不把尚未验证的组合伪装成一键能力。

使用者可以跳过引导。浏览器记住本地选择，之后默认进入概览；侧边栏底部始终保留“快速开始”
入口，允许随时回来。直接访问 `#quickstart` 不受跳过状态影响。

### 3.2 概览

概览是日常状态页，展示当前应用的 Profile、Runtime Environment、框架版本，以及配置加载、
核心能力、依赖健康、Workflow 注册和最小成功 Run 五项状态。

概览不重复列出完整组件明细、运行容量指标或全部配置字段。

### 3.3 组件

组件页将同一组件的配置、注册和健康信息合并成一行：

1. 能力类型与 Component ID；
2. 配置中选择的 Provider；
3. 当前实现与来源 Starter；
4. 装配状态；
5. 健康状态；
6. 是否属于必需组件；
7. 错误码。

### 3.4 运行

运行页只处理应用已经收到请求之后的事实：

- 运行量、成功率、失败率和耗时；
- 活跃、停滞、人工等待、数据库连接和 Outbox 积压；
- 需要处理的 Run；
- 按 Run ID 查询后，在“运行结果、模型调用、安全决策、事件链”四个 Tab 中查看完整证据；
- 模型调用展示模型、Prompt 版本、Token、耗时、重试和错误，不展示调用正文；
- 安全决策展示五阶段检查位置、Guardrail ID/版本、动作、风险、原因码和耗时，不展示业务正文
  或内容哈希；
- 按 Gate ID 查询并完成开发期人工确认。

运行页不承担配置编辑或启动装配说明。

### 3.5 配置

配置页只读展示 `/actuator/config` 的真实运行快照：

- 生效配置按“基础与运行、模型与流程、数据存储、缓存与事件、测试”分 Tab；
- 每个叶子字段展示 `ConfigOrigin`，区分框架默认、Starter 默认、`gaia.yaml`、Profile、
  环境变量和 CLI 覆盖；
- 展示配置指纹，并明确当前页面只读；
- Secret 只展示引用或脱敏结果。

配置变更继续在 `gaia.yaml`、Profile、环境变量或代码中完成，并经过 Git、CI 和部署流程生效。
Console 不创建、编辑、校验或激活 Revision，也不暗示浏览器修改已经进入运行进程。未来若需要
集中配置管理，应作为带鉴权、审计、审批和发布能力的独立 Control Plane 产品设计。

### 3.6 测试

测试页触发 Gaia Test Kit Replay，展示总体通过率、质量门禁结论和逐 Case 结果。它是开发期
质量反馈入口，不替代专业评估平台。

### 3.7 Prompt Workspace

Prompt 菜单始终显示，不再用组件 ID 隐藏框架能力。页面根据当前装配呈现三种状态：

- `disabled`：展示未启用状态，以及文件 Prompt 与 Prompt Registry 的适用差异；
- `file`：只读展示根目录、Prompt ID、版本、相对路径和内容哈希，不展示 Prompt 正文；
- `postgres`：展示完整 Registry 工作区，版本、环境指针和 Draft 导入分别放在三个 Tab。

Registry 模式：

- 版本表展示状态、内容哈希、Golden Dataset 证据和更新时间；
- 环境指针表展示 mock、sandbox、customer 当前精确版本；
- 导入只创建不可变 Draft，不能覆盖同版本内容；
- 只有通过 Test Kit 报告验证的版本可以发布；
- 回滚只移动环境指针，不改写历史 Artifact。

Prompt 写路由默认不注册。`apps/web` 已启用仍不足以获得写能力，还必须显式设置
`GAIA_DEVTOOLS_ENABLED=true`。Actuator 明确返回开发工作区是否开启；Console 不再依赖 404
推测能力。Provider 已配置但开发工作区未开启时，页面展示只读状态，不渲染失效操作。
生产 Runtime 不启用该变量。

## 4. 展示范式

API 返回对象不得直接以 JSON 作为默认界面：

- 配置使用分组表单和 Tab；
- Run、Gate 和应用状态使用指标、定义列表和事件链；
- 单个 Run 的结果、模型调用、安全决策和事件链使用同一详情区内的 Tab，不纵向重复堆叠；
- 重复对象使用表格；
- Replay 使用汇总指标和逐 Case 结果。

控件外观按数据类型选择，但只读配置页不提供可编辑交互。原始 JSON 只允许作为显式开发调试
选项，M1 不提供该入口。

## 5. 部署与安全边界

- `apps/web` 不进入 Gaia wheel；
- Console 通过 `make dev-console` 作为独立本地开发进程启动；
- 开发基础设施 Compose 不包含 Console；
- 生产部署清单不得包含 Console 镜像和端口；
- Console 只通过受认证 API 读取状态，不直接连接数据库；
- `/devtools/prompts` 写路由仅在显式开发开关下注册；
- Console 不保存 Secret 明文、客户数据或业务规则；
- 不允许浏览器临时切换 Runtime Environment 或热替换运行中组件。

## 6. 前端状态

- 服务端数据统一通过 API client；
- M1 使用 React hooks，不强制引入状态库；
- URL 可深链到概览、组件、运行、配置和测试；
- loading、empty、error 和 permission 状态完整；
- 移动端支持只读查看、Run 查询、人工确认和测试结果。

## 7. 视觉基线

- 固定左侧任务导航、顶部应用与 Profile 状态、主内容区；
- 8px 以内圆角，避免卡片套卡片；
- 页面区块以表格、定义列表、分栏和 full-width bands 为主；
- 状态颜色同时使用文字和图标，不只依赖颜色；
- 固定格式元素使用稳定网格，动态内容不得推动布局；
- 不在前端展示开发规范、施工图或架构边界说明。
